# Подключение к Reg.ru: только чтение

Эта инструкция описывает помощники чтения. Публикация первого этапа позднее отдельно разрешена и выполнена через HTTPS API; проверенный способ, резервная копия и откат описаны в DEPLOYMENT.md. Прямой SSH остаётся недоступным из-за тайм-аута.

## Рабочее подключение через HTTPS-панель

Агент успешно прошёл аутентификацию с этого компьютера через `https://server193.hosting.reg.ru:1500/ispmgr` и прочитал список сайтов через API ISPmanager. Проверка сертификата включена. Панель вернула `star40.ru` с `docroot=/www/star40.ru`; полный серверный путь приведён ниже. Файлы хостинга не изменялись.

Для следующей проверки дважды нажмите **CONNECT_HOSTING_PANEL.cmd** в папке проекта. В отдельном окне введите пароль в скрытое поле и нажмите **Connect (read only)**. Результат сохранится в `%LOCALAPPDATA%/star40/panel/status.json`; там только статус и сведения о сайтах. Пароль и токен сессии не сохраняются. Помощник выполняет только аутентификацию и запрос `webdomain`, не публикует сайт. SSH-помощник ниже остаётся отдельным вариантом после восстановления доступности порта 22.

Сервер: `server193.hosting.reg.ru`, IP `31.31.196.172`, SSH/SFTP, порт `22`, пользователь `u3596090`. DNS совпал с указанным IP. Первоначально SSH ответил, но последующие прямые соединения с рабочего компьютера завершились `Connection timed out` до запроса пароля. Успешный прямой SSH/SFTP-вход пока не подтверждён.

## Подтверждённая папка сайта

Через Shell-клиент авторизованной панели Reg.ru пользователь получил полный путь:

```text
/var/www/u3596090/data/www/star40.ru
```

В каталоге присутствуют index.html, .htaccess, assets, docs, media и остальные файлы сайта. SHA-256 index.html на сервере и ответа https://star40.ru/ полностью совпали: `c5881443213b04f6be245e59558d340b627c5c9c7f82cfcb4ebfc38dbebf4c7c`; размер обоих — 3912 байт. Корень подтверждён для файловой системы сервера. То, как этот путь отображается при SFTP (возможное ограничение домашним каталогом), нужно проверить после успешного подключения.

Файлы на хостинге не изменялись. Отдельная задача перед публикацией — восстановить прямое соединение с рабочего компьютера; причина тайм-аута ещё не установлена. Повторный ввод пароля не устраняет сетевой тайм-аут.

## Что сделать

1. **Ключ уже подтверждён.** Пользователь выполнил в Shell-клиенте авторизованной панели Reg.ru команду `ssh-keyscan -T 5 -t ed25519 127.0.0.1 2>/dev/null | ssh-keygen -lf - -E sha256`. Полученный отпечаток полностью совпал с внешним: `SHA256:T1OJXU1Kj1l/zJyoqbD957TTKmGgtelLGujOlvR0XEU`. Он внесён в помощник; обращаться в поддержку и вводить отпечаток повторно не требуется.

2. В папке `C:\Users\User\Desktop\star` дважды нажмите **CHECK_HOSTING.cmd**. Откроется локальное окно PowerShell. Альтернативная команда в Windows Terminal / PowerShell:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File "C:\Users\User\Desktop\star\scripts\inspect-hosting.ps1"
   ```

   RemoteSigned применяется только к этому процессу; системная политика не меняется.

3. Проверка подтверждённого ключа выполняется автоматически. При несовпадении вход остановится до передачи пароля; обходить такую ошибку нельзя.
4. Только при запросе `password:` введите пароль прямо в это окно и нажмите Enter. **Символы и звёздочки не отображаются — это нормально.** Если появился тайм-аут, ошибка или строка `PS C:\...>`, пароль не вводить: это уже командная строка компьютера. Не вставляйте пароль в команду, чат или `.hosting.local.json`.
5. Скрипт покажет результаты чтения и путь к локальному отчёту. Сообщите в задаче «проверка выполнена»; содержимое пароля не нужно. Отчёт будет прочитан из локальной папки для определения корня сайта.

## Что делает скрипт

Использует установленный Windows OpenSSH. Публичный ключ ранее получен через ssh-keyscan из Git for Windows и теперь независимо подтверждён через Shell-клиент панели Reg.ru. Помощник вычисляет его отпечаток, сравнивает с подтверждённым и сохраняет публичный ключ в `%LOCALAPPDATA%\star40\ssh-readonly\known_hosts`. SSH проверяет фактический ключ сервера до передачи пароля. Сохранённый изменившийся ключ не перезаписывается. При смене ключа требуется новая независимая сверка.

Проверяет соответствие DNS указанному IP и подключается по имени сервера с проверкой закреплённого ключа: `StrictHostKeyChecking=yes`. Не включает пересылку SSH-агента, портов или произвольные локальные команды. Использует фиксированную удалённую команду без интерактивной оболочки: имя пользователя, текущий каталог, список файлов верхнего уровня, поиск каталогов с star40 в имени до глубины 5, их содержимое и SHA-256 публичных файлов (index.html, манифест галереи, favicon).

Пароль получает непосредственно SSH через консоль без отображения. Скрипт не имеет параметра пароля, не читает его в переменную, не использует переменную окружения и не сохраняет пароль в файл. Не включайте стороннюю запись клавиатуры/терминальной сессии при вводе.

Отчёты сохраняются **вне репозитория**: `%LOCALAPPDATA%\star40\ssh-readonly\inspection-ДАТА-ВРЕМЯ.txt`. В них только стандартный вывод удалённой проверки, без запроса/ввода пароля. На сервер не загружается даже скрипт: команды передаются через SSH. Файлы хостинга не создаются, не редактируются и не удаляются. Сам хостинг может штатно записать факт входа в свой журнал.

Найденный каталог — кандидат до сопоставления его файлов с публичным сайтом и настройкой домена в панели. При отказе SSH повторного перебора пароля нет. Публикация не входит в эту проверку.

Документация Reg.ru: [работа по SSH на виртуальном хостинге](https://help.reg.ru/support/hosting/dostupy-i-podklyucheniye-panel-upravleniya-ftp-ssh/rabota-po-ssh-na-virtualnom-hostinge), [подключение SFTP](https://help.reg.ru/support/hosting/dostupy-i-podklyucheniye-panel-upravleniya-ftp-ssh/protokol-peredachi-dannykh-sftp).
