## Проверенный механизм HTTPS-публикации

Описание штатных форм получено через out=devel. Изменение выполняется с sok=ok. Проверку сертификата не отключать.

1. file — список каталога; file.edit без sok — просмотр текста. Для точных байтов: file.download с plid/elid **без out**. Проверять тип ответа, размер и SHA-256: JSON ошибки нельзя принять за архив.
2. file.new, filetype=1 — отдельный каталог вне публичного корня.
3. Загрузка: multipart POST на /mancgi/upload, поля mgrname=ispmgr, func=file.upload, type=data, plid, sok=ok; файловое поле filename. Загружать сначала в непубличный staging, скачивать обратно и сравнивать SHA-256 со сборкой.
4. file.unixattr с dname переименовывает, но отказывает при существующем имени. Не удалять действующий index.html ради переименования.
5. file.copyto поддерживает move=on и overwrite=on; dirlist — hex UTF-8 пути назначения из формы панели. На тестовых файлах проверены замена содержимого и исчезновение исходного файла. Это использовано для переключения HTML из staging на том же аккаунте. Внутреннюю реализацию системного rename панель не раскрывает; после операции проверены доступность сайта и точные байты.
6. Резервная копия: через file.copyto скопировать star40.ru из /www в отдельный непубличный каталог выпуска, move=off, overwrite=off. Затем вызвать file.pack для этой копии из каталога выпуска: filetype=tgz, remove_files=off, arcname=star40-before-release (простое имя без пути и расширения). Панель сама добавляет .tgz. В октябрьском выпуске пути в arcname приводили к arc_error; архивирование копии рядом с ней прошло успешно. Скачать архив и полностью прочитать его, проверив .htaccess и index.html по SHA-256.
7. file.delete — немедленное действие, а не форма: **не вызывать для просмотра или с out=devel**. Выполнять только с точными именами собственных тестовых файлов/пустого staging после проверки содержимого. Старые assets, index.html и служебные файлы хостинга не удалять.
