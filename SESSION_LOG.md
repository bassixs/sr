### Задача 1. Починка SPA-роутинга под GitHub Pages
_Статус: готово_

**Проблема.** Навигация клиентская (`history.pushState`), сервера нет — на GitHub Pages прямой заход или обновление (F5) на внутренней странице (`/sr/treatment` и т.п.) отдаёт 404, потому что такого файла на статике не существует.

**Решение.** Стандартный приём spa-github-pages: `public/404.html` кодирует запрошенный путь в query-строку и редиректит на `index.html`, а скрипт в `index.html` восстанавливает исходный путь через `history.replaceState`. Базовый путь `/sr/` → сохраняем 1 сегмент пути.

**Что сделано:**
- Создан `public/404.html` со скриптом-редиректом (Vite кладёт его в корень `dist` при сборке).
- В `index.html` в `<head>` добавлен скрипт восстановления пути.

**Проверка:** прямой заход на `/sr/treatment` в dev — страница грузится корректно, ошибок в консоли нет. Обычная навигация по сайту не сломана.

### Задача 2. Сжатие изображений
_Статус: готово_

**Проблема.** 7 PNG по 2.2–2.9 МБ (итого ~18 МБ) вшиты в бандл. Тяжело для мобильных и медленного интернета.

**Что сделано:**
- Все 7 изображений сконвертированы в WebP (качество 80, ширина ограничена 1600px) через одноразовый скрипт на `sharp`.
- Обновлены импорты в `src/App.tsx`: `../photo/N.png` → `../photo/N.webp`.
- Старые PNG удалены, временный скрипт и пакет `sharp` убраны из проекта (чтобы не замедлять деплой `npm ci`).

**Результат:** ~18 МБ → **~1.5 МБ** (сжатие ~92%). Самая тяжёлая картинка теперь 335 КБ вместо 2.98 МБ.

**Проверка:** сборка проходит, WebP попадают в `dist/assets`; в превью hero использует `1.webp`, файл отдаётся со статусом 200 и типом `image/webp`, ошибок в консоли нет.

> Если в будущем добавятся новые изображения — конвертировать так же: `npm i -D sharp`, прогнать скрипт конвертации (см. историю сессии), затем `npm uninstall sharp`.

**Коммит:** `57eeea0` — «Fix GitHub Pages SPA routing and optimize images».

### Задача 6. Доступность и Schema.org (углублённый обзор)
_Статус: готово_

Более глубокая проверка показала, что база уже неплохая: `prefers-reduced-motion` обработан, `:focus-visible` есть на всех интерактивных элементах, `lang="ru"`, по одному `<h1>`. Закрыты оставшиеся пробелы (без данных заказчика):

- **JSON-LD `MedicalOrganization`** в `index.html` — name, url, logo, image, email, регион, ИНН (`taxID`), ОГРН (`identifier`). Телефон намеренно не включён (заглушка — нельзя публиковать фейк в разметке).
- **Режим «для слабовидящих» теперь сохраняется** между визитами через `localStorage` (важно для целевой аудитории — раньше сбрасывался при каждой загрузке).
- **`aria-pressed`** на кнопке-переключателе режима.
- **Skip-ссылка** «Перейти к содержимому» (видна при фокусе с клавиатуры) + `id="main-content"` на `<main>`.

**Не сделано намеренно:** дизайн рассчитан на шрифт **Inter**, но он не подключён (рендерится системный). Для госсайта загрузка Google Fonts спорна из-за 152-ФЗ (внешние запросы с данными пользователя) — решение оставлено за заказчиком; при желании — самостоятельный хостинг шрифта.

**Проверка:** сборка успешна; JSON-LD парсится, тип `MedicalOrganization`; переключатель меняет `aria-pressed` false↔true и пишет в `localStorage`; skip-ссылка ведёт на существующий `#main-content`.
