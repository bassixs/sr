### Задача 1. Починка SPA-роутинга под GitHub Pages
_Статус: готово_

**Проблема.** Навигация клиентская (`history.pushState`), сервера нет — на GitHub Pages прямой заход или обновление (F5) на внутренней странице (`/sr/treatment` и т.п.) отдаёт 404, потому что такого файла на статике не существует.

**Решение.** Стандартный приём spa-github-pages: `public/404.html` кодирует запрошенный путь в query-строку и редиректит на `index.html`, а скрипт в `index.html` восстанавливает исходный путь через `history.replaceState`. Базовый путь `/sr/` → сохраняем 1 сегмент пути.

**Что сделано:**
- Создан `public/404.html` со скриптом-редиректом (Vite кладёт его в корень `dist` при сборке).
- В `index.html` в `<head>` добавлен скрипт восстановления пути.

**Проверка:** прямой заход на `/sr/treatment` в dev — страница грузится корректно, ошибок в консоли нет. Обычная навигация по сайту не сломана.

### Задача 2. Сжатие изображений
_Статус: готово_

**Проблема.** 7 PNG по 2.2–2.9 МБ (итого ~18 МБ) вшиты в бандл. Тяжело для мобильных и медленного интернета.

**Что сделано:**
- Все 7 изображений сконвертированы в WebP (качество 80, ширина ограничена 1600px) через одноразовый скрипт на `sharp`.
- Обновлены импорты в `src/App.tsx`: `../photo/N.png` → `../photo/N.webp`.
- Старые PNG удалены, временный скрипт и пакет `sharp` убраны из проекта (чтобы не замедлять деплой `npm ci`).

**Результат:** ~18 МБ → **~1.5 МБ** (сжатие ~92%). Самая тяжёлая картинка теперь 335 КБ вместо 2.98 МБ.

**Проверка:** сборка проходит, WebP попадают в `dist/assets`; в превью hero использует `1.webp`, файл отдаётся со статусом 200 и типом `image/webp`, ошибок в консоли нет.

> Если в будущем добавятся новые изображения — конвертировать так же: `npm i -D sharp`, прогнать скрипт конвертации (см. историю сессии), затем `npm uninstall sharp`.

**Коммит:** `57eeea0` — «Fix GitHub Pages SPA routing and optimize images».

### Задача 8. Подключение шрифта Inter (локально)
_Статус: готово_

**Проблема.** Дизайн строился под Inter (`font-family: Inter, …`), но сам шрифт не был подключён — рендерился системный (Segoe UI/San Francisco/Roboto в зависимости от ОС).

**Решение.** Локальный (self-hosted) вариативный Inter через пакет `@fontsource-variable/inter` — без внешних запросов (важно для госсайта по 152-ФЗ, в отличие от Google Fonts CDN). Выбрана **вариативная** версия, т.к. в стилях используются нестандартные веса (650, 760, 850, 950), которые статичные начертания точно не дают.

**Что сделано:**
- `npm i @fontsource-variable/inter`;
- импорт в `src/main.tsx`;
- имя шрифта в `styles.css`: `"Inter Variable", Inter, …`;
- декларация модуля в `src/vite-env.d.ts` (иначе TS ругался на side-effect import CSS).

**Проверка:** сборка успешна, woff2 в бандле; `document.fonts` показывает применённый `"Inter Variable"`, веса 400/760/900 для кириллицы отрисовываются; загружаются ровно 2 субсета (кириллица + латиница), остальные не качаются благодаря `unicode-range`; `font-display: swap` — без «мигания» невидимым текстом; ошибок в консоли нет.

_Примечание: вес 950 (используется 1 раз) выходит за верхнюю границу вариативной оси 900 и клампится к 900 — визуально незаметно._

### Задача 25. Разделение публичного текста и вопросов заказчику

_Статус: готово_

По замечанию о фразах вроде «этот блок стоит взять из материалов санатория» проведена вычитка публичных страниц и контентных массивов.

- на главной странице блок «Мифы о санаторном лечении» переписан как пользовательский текст без внутренней рекомендации;
- на странице «О санатории» блок будущей галереи переименован в нормальный пользовательский раздел «Территория и пространство»;
- рабочие комментарии по фото, инфраструктуре, врачам, ОМС, контактам, маршруту и официальным документам переформулированы как конкретные вопросы заказчику + предлагаемое решение;
